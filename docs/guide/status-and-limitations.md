# Status and limitations

This page says what is checked, what is not, and what is missing. It follows
the open items in the workspace `todo.md`. It does not claim validation
against reference software that has not been run.

## Milestones

None of the four milestones in `todo.md` is met yet.

- **M1** (Zarr from S3, global mean in seconds): no S3 or HTTP store. Local
  Zarr only.
- **M2** (Jupiter position to sub-arcsecond accuracy): the ephemeris reader
  exists, but there is no validation against JPL Horizons, and the CLI query
  needs a kernel that is not bundled.
- **M3** (lazy El Nino index): no climate index code. Anomaly, climatology and
  Nino3.4 are not implemented.

## What is checked

- Unit tests and doctests in each crate, and the CLI tests in
  `tpt-planetary-cli/tests/cli.rs`.
- `tpt-planetary-cli/tests/dataflow.rs`: a scaled-down version of the spec's
  section 7 pipeline on a synthetic dataset. It checks the lazy box mean,
  cos(lat) weighting, chunk access, UTC-TT offset, the TT-TDB bound, and
  the Earth-Sun distance against analytic values. It checks the code's own
  consistency, not reference software.
- The leap-second table: 28 entries, compared with the IERS `leap-seconds.list`
  file on 2026-11-16.
- NetCDF-3 reading: fixtures generated by SciPy's `netcdf` module.
- Zarr: round-trip tests in the array crate. The fixtures are written by this
  crate, not by zarr-python.

## What is not validated

- **Against reference software.** Nothing is compared with SOFA or ERFA
  published vectors, Astropy outputs, JPL Horizons, wcslib, zarr-python
  datasets, or netCDF4 and xarray files. Several items below are open in
  `todo.md` for this reason.
- **Constants and coefficients written from memory.** The Galactic pole
  constants, the three TDB terms, the IAU 2006 obliquity coefficients, and the
  Earth-Sun series are unvalidated. The Earth-Sun series is accurate to about
  1e-4 AU by its own documentation. The Galactic values agree with published
  M31 coordinates to the digits shown in [Time and frames](time-and-frames.md),
  which is a sanity check only.
- **EOP column positions.** The `finals2000A` column map in
  `tpt-planetary-astro/src/eop.rs` was written from memory and has not been
  checked against the IERS readme.
- **Polar-motion sign.** The `W = R2(xp) R1(yp)` convention is checked against
  `erfa.pom00` and `erfa.c2t06a` (see `docs/validation.md`).
- **TDB.** Only three terms of the series are used, so the result is an
  approximation with a truncation bound of about 1.7 ms.
- **Alt/Az.** `icrs_to_altaz_at` applies no atmospheric refraction, no annual or
  diurnal aberration, no light deflection and no parallax. Its validation
  against Astropy therefore includes the annual aberration (about 20 arcsec)
  as a known difference. The observed (refracted) place is not implemented.
- **Polar motion history.** No EOP series is bundled. `xp` and `yp` are inputs,
  and the TIO locator is the secular value `-47 uas t`. The polar-motion term
  of Eq. 5.4, which needs a polar-motion time series, is not computed.
- **Leap-second table expiry.** `EMBEDDED` is valid until 2027-06-28. After
  that, UTC conversions fail. The table must be re-checked before each release.

## Known gaps and naming issues

- `icrs_to_ecliptic_epoch_obliquity` (renamed from `icrs_to_ecliptic_at_epoch`)
  rotates by the epoch obliquity but keeps the J2000 equinox. It is not the mean
  ecliptic of date.
- True ecliptic takes a caller-supplied obliquity.
- IAU 2006 precession is available as `tpt_planetary_astro::precession` (angles
  and matrix, no frame bias). IAU 2000A_R06 nutation is available as
  `tpt_planetary_astro::nutation`: the full luni-solar and planetary series in
  longitude and obliquity, the nutation matrix, and the classical equation of the
  equinoxes `dpsi cos(eps0)` plus those complementary terms. Limits: no IAU 2000B. the complementary terms of the equation of the
  origins are included (`astro::cio`). No frame bias in the nutation matrix.
- The CIP X and Y, the CIO and TIO locators, and the ICRS to ITRS matrix are in
  `tpt_planetary_astro::cio` (IAU 2006/2000A, validated against pyerfa). There is
  no aberration, proper motion, apparent position, or typed ITRS, CIRS or TIRS
  frame. FK5 and FK4 are not implemented.
- The nutation series follow the published IERS Conventions (2010) tables,
  which include the time-varying out-of-phase amplitudes. ERFA's `nut06a` omits
  them, so the two differ by up to 5.3 uas in dpsi over 1900-2100. The difference
  is documented in `docs/validation.md`.
- No UT1 time scale type. `EopTable` interpolates UT1-UTC and polar motion
  from parsed `finals2000A` records, but no EOP data file is bundled and the
  column map is unverified (see above).
- Ephemeris: the file is read from a byte slice; memory mapping is not
  implemented (it would need `unsafe`). Light time uses one iteration, and
  apparent positions are not computed.
- WCS: TAN, SIN and AIT projections. Round trips are tested on synthetic
  headers, not against wcslib. SIP distortion is not implemented.
- The `todo.md` entry for the lazy graph says there are no binary elementwise
  nodes. The code does have them (`Expr::arith`, `compare`, `select`, `unary`).
  That todo entry is out of date.

## Array engine

Implemented: N-D data model, Zarr v2 and v3 metadata and chunk I/O, groups,
consolidated v2 metadata, gzip, zlib, lz4, shuffle and delta codecs, a
synchronous local store and an in-memory store, lazy expressions, reductions,
spherical weighting, rolling and block means, and NetCDF-3.

Not implemented:

- async store trait, HTTP, S3 and other network stores, retry and backoff,
  chunk cache, request coalescing;
- parallel chunk execution, SIMD (`tpt-simd` is blocked by its Rust 1.95
  requirement), memory-map I/O;
- Zarr v3 `transpose` and sharding codecs, zstd, Blosc, bitshuffle;
- monthly climatology group-by;
- CDF-5, NetCDF-4 and HDF5.

## CLI

`array math` writes Zarr only, and `array convert` supports int8 to float64
only. `astro convert` supports the time scales utc, tai and tt and the frames
icrs, galactic and ecliptic (mean J2000); TDB and other frames exit with 3. `ephemeris query` needs a kernel path. See
[Command line](cli.md).

## Python bindings

The Python bindings (`bindings/tpt-planetary-py`) build with maturin and pass 83
pytest cases on Windows. There
are no published wheels, no CI wheel job, and no API reference in this guide.

## Benchmarks and fuzzing

Benchmarks against xarray, netCDF4, Astropy and NumPy are not written, and no
published results exist. The fuzzing scaffold and the benchmark harness are
open items.
